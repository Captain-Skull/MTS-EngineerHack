# 0001. Кластер создаётся kubeadm, узлы настраивает Ansible

**Статус:** принято

## Контекст

Кейс требует Kubernetes на Ubuntu 24.04 с приоритетом kubeadm. Развертывание должно повторяться одной командой на одной машине, на нескольких серверах и на локальном стенде, а повторный запуск не должен ничего ломать.

## Решение

Kubernetes ставится **kubeadm**. Подготовку узлов (модули ядра, sysctl, containerd, runc, пакеты kubelet/kubeadm из pkgs.k8s.io, `kubeadm init/join`) выполняют **роли Ansible** ([`ansible/roles`](../../ansible/roles)). Конфигурация kubeadm задаётся файлом `ClusterConfiguration`, а не флагами: аудит API server, шифрование Secret в etcd, serving-сертификаты kubelet.

## Альтернативы

- **k3s / k0s** — быстрее ставятся, но это другие дистрибутивы со своими компонентами (встроенный ingress, sqlite/kine). Не соответствуют приоритету кейса и скрывают устройство кластера.
- **Kubespray** — тоже Ansible + kubeadm, но тысячи строк чужого кода с десятками опций; сложно объяснить и проверить каждую строку.
- **Shell-скрипт** — не идемпотентен без большого объёма ручных проверок.

## Последствия

- Каждый шаг виден в коде; повторный `make cluster` даёт `changed=0` — это проверяет CI.
- Одна и та же роль работает для all-in-one (CI, одна VM) и для нескольких узлов — меняется только inventory.
- Обновление версии Kubernetes требует процедуры `kubeadm upgrade`, поэтому Renovate обновляет Kubernetes только в пределах патч-версий.
