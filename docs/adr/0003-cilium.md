# 0003. Cilium без kube-proxy и Node IPAM вместо MetalLB

Статус: принято.

## Контекст

Нужны сеть подов, NetworkPolicy и способ довести внешний трафик до Gateway на обычных машинах, где нет облачного балансировщика.

## Решение

Cilium полностью заменяет kube-proxy, и Service работают на eBPF вместо iptables. Внешний адрес для Service типа LoadBalancer выдаёт Cilium Node IPAM: адресами сервиса Envoy становятся IP узлов. Сетевую картину показывает Hubble (UI и метрики).

## Альтернативы

- У Flannel нет NetworkPolicy.
- Calico зрелый и умеет NetworkPolicy, но наблюдаемости уровня Hubble у него из коробки нет, а для LoadBalancer всё равно нужно отдельное решение.
- MetalLB или Cilium LB-IPAM с L2/BGP дают выделенный плавающий адрес. Для этого нужен свободный диапазон в сети, и на одной машине, в Multipass и на GitHub runner он устроен по-разному. Node IPAM ведёт себя одинаково во всех трёх средах.

## Последствия

- Один компонент закрывает CNI, Service, NetworkPolicy, LoadBalancer и сетевую наблюдаемость.
- Gateway доступен по IP любого узла (адресов несколько), но если узел пропал, клиенту придётся самому перейти на другой адрес. В production лучше Cilium LB-IPAM с анонсом выделенного адреса по BGP или L2.
- После восстановления etcd Cilium нужно перезапустить, потому что его eBPF-таблицы помнят старое состояние сервисов. Это учтено в `ansible/etcd-restore.yml`.
