# 0006. Helmfile и Make для платформы, без GitOps-контроллера

Статус: принято. Для приложений позже добавлен GitOps, см. [0014](0014-gitops-argocd.md).

## Контекст

Платформа состоит примерно из двух десятков Helm-релизов, которые зависят друг от друга (сначала CRD, потом операторы, потом ресурсы). Эксперт должен развернуть всё одной командой на чистой машине и до применения увидеть, что изменится.

## Решение

Helmfile описывает все релизы с закреплёнными версиями и зависимостями (`needs`) в [`helmfile/helmfile.yaml.gotmpl`](../../helmfile/helmfile.yaml.gotmpl). Запускается всё через Make (`make deploy`, `make diff`, `make test`, `make chaos`). Свои ресурсы оформлены собственными Helm-чартами в [`charts/`](../../charts).

## Альтернативы

- Argo CD или Flux постоянно сверяют кластер с Git. Но им нужен доступный кластеру репозиторий и отдельный bootstrap самого контроллера, а результат развертывания видно в UI контроллера, а не в терминале. Для разового развертывания у эксперта это лишний слой.
- Terraform с helm provider хранит состояние в state-файле, который тоже надо где-то держать, и плохо справляется с CRD, появляющимися прямо во время применения.
- Голый `kubectl apply` манифестов не даёт ни шаблонов, ни версий, ни порядка установки.

## Последствия

- `make diff` показывает изменения заранее. CI проверяет идемпотентность: после повторного применения `helmfile diff` пуст.
- Сверка с Git происходит только при запуске. Ручное изменение в кластере продержится до следующего `make platform`.
- Перейти на Argo CD несложно: каждый релиз helmfile становится `Application` с теми же values. Для приложений так и сделано в [0014](0014-gitops-argocd.md).
