# 0006. Helmfile + Make для платформы, без GitOps-контроллера

**Статус:** принято; для приложений дополнено GitOps — [0014](0014-gitops-argocd.md)

## Контекст

Платформа — около двух десятков Helm-релизов с зависимостями (CRD → операторы → ресурсы). Эксперт должен развернуть всё одной командой на чистой машине и увидеть, что изменится до применения.

## Решение

**Helmfile** описывает все релизы с зафиксированными версиями и зависимостями (`needs`) в [`helmfile/helmfile.yaml.gotmpl`](../../helmfile/helmfile.yaml.gotmpl). Точка входа — **Make** (`make deploy`, `make diff`, `make test`, `make chaos`). Собственные ресурсы оформлены собственными Helm-чартами в [`charts/`](../../charts).

## Альтернативы

- **Argo CD / Flux** — GitOps с постоянной сверкой. Требует доступного кластеру Git-репозитория и bootstrap самого контроллера, а результат развертывания виден не в терминале, а в UI контроллера. Для одноразового развертывания эксперта — лишний слой.
- **Terraform (helm provider)** — состояние в state-файле, которое нужно хранить; хуже работает с CRD, которые появляются во время применения.
- **`kubectl apply` манифестов** — нет шаблонизации, версий и порядка установки.

## Последствия

- `make diff` показывает изменения до применения. Идемпотентность (`helmfile diff` пуст после повторного применения) проверяется в CI.
- Сверка с Git не постоянная, а по запуску: ручное изменение в кластере вернётся только при следующем `make platform`.
- Переход на Argo CD прост: каждый релиз helmfile становится `Application` с теми же values. Для приложений это сделано в [0014](0014-gitops-argocd.md).
