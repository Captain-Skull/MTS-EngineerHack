# 0007. Собственный CA в cert-manager вместо ACME

Статус: принято.

## Контекст

Gateway должен отдавать HTTPS. Стенд живёт в закрытой сети (Multipass, GitHub runner) на домене `demo.test`, которого нет в публичном DNS.

## Решение

cert-manager создаёт самоподписанный корневой CA и `ClusterIssuer` на нём, а затем выпускает и продлевает wildcard-сертификат `*.demo.test` для Gateway. Сертификат CA выгружается в `.state/ca.crt`, так что `curl --cacert` проверяет TLS по-честному, без `-k`.

## Альтернативы

- Let's Encrypt (ACME) выдаёт сертификаты, которым доверяют браузеры, но ему нужны публичный домен и доступный снаружи HTTP-01 или DNS-01. В закрытом стенде это невозможно.
- Сертификат, сделанный вручную через openssl, никто не продлит и за сроком не проследит.

## Последствия

- Весь жизненный цикл сертификатов автоматизирован и виден в мониторинге, есть алерты `CertificateExpiringSoon` и `CertificateNotReady`.
- Браузер ругается на недоверенный сертификат. Для публичного домена достаточно поменять `ClusterIssuer`, Gateway трогать не нужно.
