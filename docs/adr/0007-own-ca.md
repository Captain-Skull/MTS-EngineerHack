# 0007. Собственный CA в cert-manager вместо ACME

**Статус:** принято

## Контекст

Gateway должен отдавать HTTPS. Стенд работает в закрытой сети (Multipass, GitHub runner) на домене `demo.test`, которого нет в публичном DNS.

## Решение

**cert-manager** создаёт самоподписанный корневой CA и `ClusterIssuer` на его основе, а затем выпускает и продлевает wildcard-сертификат `*.demo.test` для Gateway. Сертификат CA выгружается в `.state/ca.crt`, и `curl --cacert` проверяет TLS по-настоящему, без `-k`.

## Альтернативы

- **Let's Encrypt (ACME)** — доверенные браузерами сертификаты, но нужны публичный домен и доступность HTTP-01 или DNS-01. В закрытом стенде невозможно.
- **Сертификат, созданный вручную openssl** — нет автоматического продления и мониторинга срока действия.

## Последствия

- Полный жизненный цикл сертификатов автоматизирован и наблюдаем: алерты `CertificateExpiringSoon` и `CertificateNotReady`.
- Браузер предупреждает о недоверенном сертификате. Для публичного домена меняется только `ClusterIssuer`, Gateway остаётся прежним.
