# 0009. Kyverno, проверка подписи в режиме fail-closed

**Статус:** принято

## Контекст

CI подписывает образ Fluentd (cosign keyless). Подпись бесполезна, если кластер её не проверяет: в реестр мог попасть образ в обход CI, а тег можно перезаписать.

## Решение

**Kyverno 1.19** с политиками на CEL ([`charts/policies`](../../charts/policies)):
- `ImageValidatingPolicy` допускает образы `ghcr.io/captain-skull/*` только с подписью workflow `image.yml` из ветки `main` (OIDC-издатель GitHub, identity, запись в Rekor) и закрепляет проверенный образ по digest;
- `ValidatingPolicy` требует digest для всех образов в namespace `demo`.

Webhook работает в режиме **`failurePolicy: Fail`**: если проверка невозможна, под не создаётся.

## Альтернативы

- **OPA Gatekeeper** — политики на Rego; проверка подписей образов только через внешний провайдер данных.
- **ValidatingAdmissionPolicy** (встроена в Kubernetes) — подходит для проверки digest, но не умеет проверять подписи.
- **Sigstore policy-controller** — проверяет только подписи; для остальных политик нужен второй движок.
- **`failurePolicy: Ignore`** (fail-open) — сбой Kyverno не мешает работе кластера, но тогда неподписанный образ пройдёт ровно в момент сбоя.

## Последствия

- Цепочка поставок замкнута: собрано CI → подписано → в кластере запускается только подписанное.
- Fail-closed делает Kyverno критичным компонентом. Поэтому у него 2 реплики с PDB и распределением по узлам, алерт `KyvernoAdmissionUnavailable`, а `make chaos` проверяет drain узла с работающим webhook.
- Создание пода с собственным образом требует доступа к GHCR и Rekor.
- В CI образ из исходников pull request называется `ci.local/...`: он не опубликован и не подписан, поэтому вне области политики. Сама политика в CI работает в режиме `Deny` и проверяется на опубликованном образе.
- Проверка подписи действительно работает: тот же образ отклоняется, если доверять другому подписанту (smoke-тест).
