# 0012. CIS Kubernetes Benchmark как защита от регрессий, с явными отклонениями

**Статус:** принято

## Контекст

kube-bench проверяет узлы по CIS Kubernetes Benchmark. Первый прогон: 19 FAIL. Часть требований противоречит другим целям проекта (наблюдаемость control plane) или неприменима к нашей архитектуре (нет kube-proxy).

## Решение

Исправить всё, что не мешает другим целям: профилирование, ротация аудита, проверка сертификата kubelet, срок жизни токенов, права на файлы, владелец данных etcd. Оставшиеся отклонения перечислены **в коде** [`scripts/cis-bench.sh`](../../scripts/cis-bench.sh) с обоснованием. Скрипт падает при любом FAIL вне списка; `make cis` выполняется в CI.

Принятые отклонения:
- **1.3.7, 1.4.2:** controller-manager и scheduler слушают IP узла, чтобы Prometheus собирал их метрики. `/metrics` защищён аутентификацией и авторизацией Kubernetes.
- **4.3.1:** проверка метрик kube-proxy — kube-proxy нет, его функции выполняет Cilium.

## Альтернативы

- **`bind-address=127.0.0.1` и отказ от метрик controller-manager и scheduler** — меньше поверхность атаки, но control plane становится «чёрным ящиком» для мониторинга.
- **Сайдкар-прокси или Prometheus с `hostNetwork`** — формально проходит проверку, но добавляет привилегированный компонент, что хуже исходного отклонения.
- **Порог по числу FAIL** — пропускает замену одного нарушения другим. Список конкретных проверок строже.

## Последствия

- Итог на трёх узлах: 110 PASS, 5 FAIL (все принятые), WARN — ручные организационные проверки.
- Используется CIS 1.12 — последняя версия для kubeadm в kube-bench 0.16. Бенчмарка для Kubernetes 1.36 пока нет, версия задаётся явно и меняется переменной `CIS_BENCHMARK`.
- Изменения конфигурации kubeadm применяются и к работающему кластеру (перегенерация манифестов static pods), поэтому исправления доходят до существующих стендов, а не только до новых.
