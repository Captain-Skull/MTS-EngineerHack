# 0014. GitOps для приложений: Argo CD поверх платформы из helmfile

Статус: принято, дополняет [0006](0006-helmfile.md).

## Контекст

Платформу ставит helmfile по команде ([0006](0006-helmfile.md)), поэтому сверка с Git происходит только при запуске. Ручное изменение в кластере живёт до следующего `make platform`. Приложениям, которые меняются часто, нужна постоянная сверка с Git и выкатка без прямого доступа разработчика к кластеру.

## Решение

Ответственность поделена так:
- helmfile делает bootstrap платформы: CNI, шлюз, сертификаты, мониторинг, политики и сам Argo CD;
- Argo CD 3.5 ([`charts/gitops`](../../charts/gitops)) ведёт приложения. `Application rollout` синхронизирует `charts/rollout` из репозитория с `automated: {prune, selfHeal}`. Проект `apps` разрешает брать код только из этого репозитория и разворачивать его только в нужные namespace, а типы ресурсов перечислены явно (кластерных среди них нет).

После синхронизации выкатку выполняет Flagger ([0013](0013-flagger.md)). Argo CD отвечает за то, что должно быть в кластере, а Flagger за то, как безопасно туда перейти.

Установка урезана под ресурсы стенда: нет Dex и notifications, всё в одной реплике, около 400 МБ памяти. UI открывается через Gateway (`argocd.demo.test`), TLS терминирует Envoy.

## Альтернативы

- Можно было завести под Argo CD всю платформу (app of apps). Подход стал бы единым, но Argo CD сам зависит от CNI, шлюза и CRD, которые должны появиться раньше него. Bootstrap всё равно нужен, а перенос всех 20 релизов сильно увеличил бы риск поломки.
- Flux почти такой же по возможностям, но без встроенного UI, который удобен для демонстрации.
- Если оставить только helmfile, не будет ни постоянной сверки, ни самовосстановления.

## Последствия

- Ручное изменение ресурса приложения откатывается за секунды. Smoke-тест удаляет NetworkPolicy и проверяет, что она вернулась.
- Кластеру нужен доступ к GitHub. Источник один, публичный репозиторий, по умолчанию ветка `main`. В CI Argo CD синхронизирует проверяемый коммит pull request (`GITOPS_REVISION`), так что изменения чарта проверяются ещё до слияния.
- Менять приложение через `kubectl` бессмысленно, Argo CD всё равно вернёт как было. `make rollout` задаёт новую версию через `Application`, так же, как это сделал бы коммит.
- Памяти нужно примерно на 400 МБ больше, но минимальные 8 ГБ из требований остаются в силе.
