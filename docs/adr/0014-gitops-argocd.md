# 0014. GitOps для приложений: Argo CD поверх платформы из helmfile

**Статус:** принято, дополняет [0006](0006-helmfile.md)

## Контекст

Платформу ставит helmfile по команде ([0006](0006-helmfile.md)): сверка с Git происходит только при запуске, и ручное изменение в кластере живёт до следующего `make platform`. Для приложений, которые меняются часто, нужна постоянная сверка с Git и выкатка без доступа разработчика к кластеру.

## Решение

Разделение ответственности:
- **helmfile** — bootstrap платформы: CNI, шлюз, сертификаты, мониторинг, политики, сам Argo CD;
- **Argo CD 3.5** ([`charts/gitops`](../../charts/gitops)) — приложения: `Application rollout` синхронизирует `charts/rollout` из репозитория с `automated: {prune, selfHeal}`. Проект `apps` ограничивает источник этим репозиторием, а назначение — нужными namespace и перечнем типов ресурсов (без кластерных).

Выкатку после синхронизации выполняет Flagger ([0013](0013-flagger.md)): Argo CD отвечает за «что должно быть», Flagger — за «как безопасно перейти».

Установка урезана под ресурсы стенда: без Dex и notifications, по одной реплике, около 400 МБ памяти. UI доступен через Gateway (`argocd.demo.test`), TLS терминирует Envoy.

## Альтернативы

- **Argo CD для всей платформы (app of apps)** — единый подход, но Argo CD сам зависит от CNI, шлюза и CRD, которые должны появиться раньше него; bootstrap всё равно нужен, а перевод всех 20 релизов — большой риск перед сдачей.
- **Flux** — близкий по возможностям, но без встроенного UI, который удобен для демонстрации.
- **Только helmfile** — нет постоянной сверки и самовосстановления.

## Последствия

- Ручное изменение ресурса приложения откатывается за секунды — smoke-тест удаляет NetworkPolicy и проверяет восстановление.
- Кластер должен иметь доступ к GitHub; источник — публичный репозиторий, по умолчанию ветка `main`. В CI Argo CD синхронизирует проверяемый коммит pull request (`GITOPS_REVISION`), поэтому изменения чарта проверяются до слияния.
- Изменения приложения через `kubectl` бессмысленны: Argo CD их отменит. `make rollout` задаёт новую версию через `Application` — как это сделал бы коммит.
- Плюс около 400 МБ памяти; минимальные требования (8 ГБ) не меняются.
